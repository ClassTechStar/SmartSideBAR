# 核心链路回归清单 (手工 E2E)

> 用途：发布前对 6 条主链路做手工回归。每条链路需在下方 DPI / 显示器矩阵中至少覆盖一次。
> 前置：全新安装（清空 `%APPDATA%\SeewoSidekick` 与 `%ProgramData%\SeewoSidekick`），或从「设置 → 运行诊断」确认各服务就绪。

## 环境矩阵

| 维度 | 取值 |
|------|------|
| DPI / 缩放 | 100% / 125% / 150% / 200% |
| 显示器组合 | 单屏 / 双屏（副屏在左 / 右 / 上 / 下） |

> 最低覆盖要求：`截图`、`长截图`、`批注` 三条链路 × 至少 3 种缩放 × 至少 2 种显示器组合；其余链路单屏 + 一种缩放即可。

---

## 1. 区域截图

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 点击 rail「区域截图」图标 | 屏幕出现遮罩层 + 十字光标 |
| 2 | 拖拽框选区域 | 选框实时显示，四角有装饰角，显示尺寸标签 |
| 3 | 点击「确认截图」 | 侧边栏恢复；通知「区域截图已保存」 |
| 4 | 打开保存目录 | 存在 `seewo-capture-<时间戳>.png`，内容与框选像素级对齐（误差 ≤2px） |
| 5 | 重复 1-4，改在副屏框选 | 副屏裁剪区域正确，无整体偏移（P0-3） |

验收：主屏 + 副屏各一次，裁剪内容与选框对齐。

## 2. 屏幕批注

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 点击 rail「批注」图标 | 出现透明批注窗口 + 工具栏 |
| 2 | 用笔/鼠标书写、画箭头、画矩形 | 笔迹实时渲染 |
| 3 | 希沃触屏单指书写 | 可书写，无鼠标兼容双笔（P0-5）；抖动被过滤 |
| 4 | 点「撤销」 | 回退上一步，按钮禁用态随撤销栈刷新（D3） |
| 5 | 点「仅笔迹」保存 | 导出透明背景 PNG（只含批注） |
| 6 | 点「含截图」保存 | 导出「屏幕背景 + 笔迹」合成 PNG（P1-8） |

验收：两种导出各产出一张 PNG，内容符合预期。

## 3. 长截图

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 点击 rail「长截图」图标 | 弹出窗口选择面板，列出可见窗口 |
| 2 | 选择目标窗口 | 开始倒计时（倒计时在侧边栏可见时播放，D7） |
| 3 | 等待自动滚动 + 拼接 | 进度条推进；完成后通知保存路径 |
| 4 | 打开长图 | 内容连贯、无错位（跨屏窗口在副屏也正确，P0-7） |
| 5 | 20 帧 1080p 场景 | 总耗时 ≤ 60s（P1-1） |

验收：目标窗口位于副屏、系统缩放 125%/150%/200% 时，首帧裁剪与窗口实际位置一致。

## 4. 录屏

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 设置 → 录屏：改 fps=30、麦克风=开，保存 | 参数写入 config（P1-7） |
| 2 | 点击 rail「录屏」 | 开始录制，出现隐藏录屏窗口与状态 |
| 3 | 录制 10s 后停止 | 保存文件；「最近文件」出现该录屏（D6） |
| 4 | 检查文件 | 为 MediaRecorder 实际 mimeType 对应扩展名（WebM，无 MP4） |

验收：改 fps/mic 后生效；录屏结束后能定位到产物文件。

## 5. USB 监控

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 插入 U 盘 | 弹出通知 + 提示音；rail 徽标/USB 面板出现该盘 |
| 2 | 插入移动硬盘 | 显示「移动硬盘」标签 + 型号（中文卷标正确解码） |
| 3 | 拔出设备 | 从列表消失 |
| 4 | 空闲观察 10 分钟 | PowerShell 进程创建次数 ≤ 3（P1-3） |

验收：U 盘 / 移动硬盘 / 光驱三类均能正确识别；`ignoreTypes` 中类型被过滤（D15）。

## 6. 定时提醒

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 新建一次性提醒（1 分钟后） | 到时弹出通知 + 铃声 |
| 2 | 新建周期提醒（每 5 分钟） | 到点重复触发 |
| 3 | 点击贪睡 | 贪睡期内不重复触发，过期后恢复 |
| 4 | 空闲观察 10 分钟 | `config.json` 写入次数为 0（P1-2） |

验收：一次性/周期/贪睡三条路径均符合预期。

## 7. 性能预算核对（P2-8）

> 用 `npm run win` 产出安装包后，在目标教学一体机（或等效 Windows 环境）实测。
> 提供自动化测试脚本 `scripts/bench-p28.mjs`，也可手动观测。

**自动化方式：**
```bash
# 自动检测默认安装路径
node scripts/bench-p28.mjs

# 指定 exe 路径 + 自定义观测时长 (默认 10 分钟)
node scripts/bench-p28.mjs --exe "C:\Users\xxx\AppData\Local\Programs\SmartSideBAR\SmartSideBAR.exe" --duration 600

# 使用构建产物测试 (无需安装)
npm run win && node scripts/bench-p28.mjs --exe dist\win-unpacked\SmartSideBAR.exe
```

脚本自动完成：冷启动计时 → 5 分钟空闲内存/CPU 采样 → USB 设备识别验证 → 10 分钟 PowerShell 进程创建计数 → 输出汇总表格 + `dist/perf-report.json`。

| 指标 | 预算 | 实测记录 | 结果 |
|------|------|---------|------|
| 安装包体积 | ≤ 110 MB | 81.6 MB（构建机实测） | 达标 |
| 冷启动时间 | ≤ 3 s | ___ s | ☐ |
| 空闲内存占用 | ≤ 220 MB | ___ MB | ☐ |
| 空闲 CPU（无设备事件） | 稳定 < 2% | ___ % | ☐ |
| 空闲 10 分钟 PowerShell 进程创建次数 | ≤ 3 | ___ 次 | ☐ |

### 核对步骤

1. 全新安装后，记录从双击启动到侧边栏可见的耗时（冷启动）。
2. 侧边栏就绪后静置 5 分钟，读空闲内存与 CPU（USB 监听器健康时应为低频巡检，见 C2/P1-3）。
3. 观察 10 分钟内是否有周期性 PowerShell 进程创建（空闲期应几乎无，输入法常驻化后见 C5）。
4. 超标项应给出裁剪方案（如按需加载 sharp、降低缩略图上限等），记录到 `docs/project-audit-and-roadmap.md`。
